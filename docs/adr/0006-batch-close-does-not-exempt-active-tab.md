# 批量关闭不豁免当前激活标签

关闭类动作的靶子包含当前激活标签时不排除它 —— 「关闭本组全部」就是全关,哪怕这会让 Chrome 关掉弹窗本身。

理由:关掉激活标签时 Chrome 必须把激活权交给另一个标签,弹窗随之失去焦点关闭(仓库里已有同一现象的记录:`settings.js` 的归档路径必须**先**把未读标记写进 storage,**再**调 `tabs.remove`)。豁免 active 能保住弹窗和撤销条,代价却是把「全部」偷换成「其余」:当 active 就在该组时,菜单里「关闭本组其余」与「关闭本组全部」的靶子几乎重合,用户再也说不清自己在关什么。语义清晰优先于反馈可见。

## Consequences

- 靶子含 active 的批量关闭会连弹窗一起关掉,当场看不到撤销条;而撤销栈(`undo.js`)是内存态,随弹窗一起消失。**接受这个代价的前提是这条会杀掉弹窗的路径必须先把撤销快照写进 `chrome.storage.session`**,让下次打开弹窗仍能 ⌘Z 救回。单关路径(✕)保持内存态不动 —— 不为一个精确点击的动作重做撤销模型。
- 单关路径(✕)早已是这个行为(`closeTab` 无 active 保护),本次只是不再为批量动作单独开例外 —— 不引入"单关会关掉 active、批量却不会"这种新的不一致。
- 真机现象(关掉 active → 弹窗立即关闭)由用户确认与现状一致,未在自动化里复现(弹窗 UI 无法 headless 驱动)。
