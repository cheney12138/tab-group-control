# 归档是一次性 URL 快照(stash 语义)

归档的实现是一行简单的选择:拍下「组名+颜色+标签 URL 清单」存进 storage.local,关掉标签。重新打开 = 在弹窗所在窗口 `tabs.create` 全新加载、归入以归档卡命名的组,随后删除归档卡。快照不含页面现场(滚动/表单/历史)、不含标签序、窗口归属与 pinned;同 URL 副本拍平为一条。

被否掉的三条路,以及为什么不要再提:

- **工作区模板(卡片永驻、反复实例化)**:与"暂存腾地方"的核心场景相悖,卡片永驻会让收纳盒无限淤积;要模板有书签。
- **富状态恢复(滚动位置、表单、会话历史)**:扩展 API 拿不到页面现场,sessions 又不可控(回收策略、激活跳窗)。URL 快照语义跨重启存活、行为完全可预期,这是它立身之本。因此动作定名「重新打开」而非「恢复」,从文案上杜绝"原样回来"的预期。
- **同步到云端 / storage.sync**:本插件无账号机制,归档卡是"本机刚才关掉的现场",跨机同步没有上下文意义,引入云端只会把功能性插件拖成系统。

衍生约定:重新打开只在**全部标签创建成功**后才焚毁归档卡(部分失败不得丢数据);归档落点=弹窗所在窗口(跟随注意力,不记历史窗口);归档组名命中规则组名时,该组回归规则引擎托管,这是规则一致性的正常推论。
