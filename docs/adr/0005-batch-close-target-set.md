# 批量关闭的靶子定义:数据源口径 + 运行时实例 + 组内时间序

标签右键菜单的关闭类动作,靶子集合由三条轴定死:取值口径是**数据源**(Chrome 里的真实标签),作用域里的"组"是**运行时分组实例**(`tab.groupId` + 所属窗口),
有序动作(`下方`)的序是**组内 `lastAccessed` 倒序**。

## 轴一:取数据源,不取当前视图

理由:搜索框是常驻状态,用户经常一边输着关键字一边操作。靶子若跟着过滤集走,同一句「关闭本组其余 (9)」在前一秒和后一秒能关掉的东西不一样 —— 破坏性动作必须可预期,而视图是瞬时状态。

推论:

1. 菜单项内嵌的数量按数据源算,不是按可见行数算。它是预告,也是防呆:屏幕上只看得到 3 行却显示「(12)」是**正确**行为。
2. **计数单位是标签, 定界单位是行**。列表把同 URL 的多个副本聚合成一行且不显示副本数,所以「其余」和「下方」都先把锚点那一行的成员(代表 + 同组副本,与作用域求交后)整体摘出去,再取剩下的 —— 一份副本同时落在"要关"和"要留"两个集合里,就是漏下用户看不见的活标签。
3. **失效则不给入口**。若锚点标签不在算出来的作用域里(理论上不该发生),「其余」「下方」一律返回空靶子、菜单项禁用置灰 —— 绝不允许它悄悄退化成「全部」。

## 轴二:"组"取运行时实例,不取 `groupKey`

`groupKey(group)` 是**身份**(`组名|颜色`,`format.js`),它跨重启稳定、且**跨窗口可重名**;搜索模式的分区正是按身份合并的(`render.js:195`),所以两个窗口里同名的组会合成分区,未分组区更是全局哨兵 `__ungrouped__`。浏览模式的分区却是按 `(窗口, 分组)`(`render.js:229`)。

两种分区身份并存,若作用域跟着 `groupKey` 走,同一个菜单项在两种模式下的靶子不是一个东西(搜索态会跨窗口关闭)。所以作用域一律取运行时实例:窗口内的那个具体 tab group。**未分组**同理 —— 它是"本窗口内未分组的标签",不是跨窗口的一坨。

代价:搜索态下,一个分区里可能混着别的窗口的同名组,`(n)` 会小于该分区行数。因此菜单项文案必须**带上组名**消歧(「关闭「codeconv」全部标签 (5)」),让数量差有解释。

## 轴三:「下方」的序取组内时间序,不取屏幕序

「关闭本组下方标签」的靶子 = **该组内按 `lastAccessed` 倒序排在该行之后的全部标签**(同一时刻用 `tab.index` 兜底),与当前搜索词无关。

理由:默认(分组)视图里,面板序本来就是 `lastAccessed` 倒序(`render.js:244`),所以这个定义在绝大多数场景下与"屏幕上在它下面的行"**严格相等** —— "面板从上往下"这个原意完整落地。一旦搜索框有字,组内排序会被匹配质量接管(`search.js:277`),此时若改跟屏幕序,同一个动作在"打字前 / 清空搜索框后"关掉的会是另一批标签 —— 破坏性动作的靶子绝不能跟着输入框内容漂移。

代价:搜索态下,屏幕上"下面"的行未必是被关的行,`(n)` 是唯一预告 —— 这正是轴一"数量即防呆"的用武之地。

推论:平坦视图(最近使用 / 当前窗口 / 命令模式)里既没有分组头(`render.js:182`),行上也没有所属组的视觉线索(`group-dot` 只长在分组头上),组级动作是"盲关";仍然照给不搞视图分叉,靠"文案带组名"消歧。

## Considered Options

- **视图口径**(靶子 = 当前渲染的可见行):符合"所见即所得"的直觉,但破坏性动作的靶子会随搜索词漂移。
- **窗口口径**(Chrome 标签栏 index 顺序,无视分组边界):即 Chrome 原生「关闭右侧标签页」的语义,但会跨组拆掉别人的分组,与"以分组为锚点"的契约冲突,且原生已覆盖,重复建设过不了 ADR-0004 的成本关。
- **全列表口径**(含其他窗口的标签):列表里确实混着其他窗口的标签,一次点击跨窗口批量关闭,不可接受。
- **`groupKey` 口径**(组名+颜色):与域模型的「分组」身份一致,但在搜索态下等于跨窗口关闭,与上一条同罪。
