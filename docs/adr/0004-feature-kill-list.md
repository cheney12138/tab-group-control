# 功能斩杀清单(准入三关的否决记录)

功能准入流程(2026-09 立):候选功能须全过三关——①契约关(锚定分组 + 纯本机,ADR-0002)②痛点关(真实用户近期真痛过,"可能会用到"不立案)③成本关(复杂度增长与身位相称)。本文档记录被斩杀者,防止半年后换个说法重提。

## 斩杀记录

- **冻结替代关闭(discard 老标签)**:Chrome Memory Saver 原生已覆盖,扩展已有休眠徽标可见状态;再造一层冻结管理是重复建设。斩于契约关+成本关。
- **全文搜索页面内容**:需注入全部页面 + 建索引 + 存快照,复杂度超过现有代码一半,只为低频场景。斩于成本关。
- **标题关键词规则(标题含"订单"则归组)**:标题是动态不可控数据,规则间会互相打架;是范围蔓延成通用标签管理器的第一步。斩于契约关。

## 同期过堂通过者(简记)

- **/r 最近关闭**:真实高频痛点,成本可控(sessions API 现成)。
- **路径规则**:多环境开发的同域多项目场景真实,引擎改动收敛在 rules-match.js。
- **归档卡展开看 URL 清单**:纯 UI 小件,无需过堂,随做。
- **手动建组 / 改名改色 / 解散**:ADR-0002 把"先给身份"写成管理能力的门槛,却一直只有规则引擎能发身份 —— 手动路径是补上这半边,不是放宽门槛(散标签仍不可归档)。过三关:锚定分组(契约)、脱离标签栏后调不了顺序/建不了组(痛点)、复用 background 队列与既有唯一性口径(成本)。
