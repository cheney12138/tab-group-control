# 换肤协议:系统 token 契约 + 主题资产白名单

第二套主题(水墨)把第一套(Linear)验证通过的惯例压成正式契约,赶在第三套主题出现之前。

## 决策

1. **系统 token 是唯一接线层**。组件 CSS 只准消费系统 token,禁止写死色值、禁止主题判断;主题块垄断 `[data-theme="..."]` 命名空间,必须为全部视觉 token 赋值(否则就是在"白嫖"别人,死主题一删就崩——本次水墨曾白嫖默认主题 19 个视觉 token,已补齐)。度量基座(间距/圆角/字号线)主题无关,存放于 `:root`,主题可覆盖、无义务。
2. **默认主题不存在**。原 `:root` 的 slate 默认主题是不可达死代码(html 恒有 data-theme),已删除。`data-theme` 缺省/未知值一律按 linear 渲染。
3. **主题覆盖层合法化但有边界**。主题可在自有命名空间覆盖装饰类属性(颜色/字体/背景/边框/遮罩);禁动布局骨架(尺寸/flex/grid 结构/定位),确需动骨架的是「主题资产」特例,必须块级注释 + 在 docs/theming.md 登记。`!important` 只准用于对抗基础层同属性。
4. **明暗是主题的自由**。每主题显式声明 `color-scheme`;暗色变体做 `data-theme` 内部 media 分支(同族不同相),不开新主题名。
5. **JS 表驱动**。主题判断一律经 `THEME_ASSETS` 表 + `themeAssets()` 单点取资产(组色映射、墨团、滑块挑出量),禁止 `dataset.theme === '...'` 散点比较;新主题 = 表里加一行。

被否掉的路:全面禁止覆盖层(水墨独有的美学件没法收敛成共享组件,会污染基础层);保留默认主题当"token 对照表"(文档会烂,docs/theming.md 才是活规范)。

## 主题义务清单(强制)

① 全部视觉系统 token ② 5 个 accent 变体值 ③ 9 色 Chrome 组色映射。operational 检查表见 `docs/theming.md`。
